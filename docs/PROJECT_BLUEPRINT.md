# 프로젝트 구조 및 개발 청사진

## 목표와 구현 경계

고등학생이 화면을 조작하고, 먼저 예측하고, 관찰 결과를 기록하면서 케플러 법칙을 스스로 설명하도록 돕는 4차시 웹 애플리케이션이다. 현재 버전은 공통 내비게이션과 화면 체계, 1차시 제1법칙 탐구 화면의 인터랙션 골격, 순수 물리 함수 기반만 제공한다. 2~4차시의 실제 시뮬레이션 및 자료 연결은 다음 개발 단계에 남긴다.

## 디렉터리

```text
src/
  content/       차시 메타데이터와 이후 학습 자료
  physics/       UI와 독립된 SI 단위 물리 계산 함수
  features/      차시별 시뮬레이션·탐구 기능 (다음 단계에서 추가)
  ui/            앱 셸, 공통 컴포넌트, 디자인 토큰/스타일
  main.tsx
docs/            교육 기획 및 구현 로드맵
.github/workflows/ GitHub Pages 배포
```

현재는 초기 골격을 간결하게 유지했다. 차시별 기능이 늘어날 때 `features/lesson-01-orbit`, `features/lesson-02-laws`, `features/lesson-03-transfer`, `features/lesson-04-mission-data`처럼 분리하고 공통 UI만 재사용한다.

## UI 원칙

- 매 차시의 중심을 탐구 질문, 조작 가능한 관찰 창, 학생 기록으로 둔다.
- 학생이 먼저 예상하고 조건을 바꿔 비교한 뒤 개념 설명을 읽도록 점진적으로 안내한다.
- 궤도 그림은 설명용 시각화이며 과학 계산은 별도의 물리 모듈에서 수행한다.
- 색상만으로 상태를 구별하지 않고 텍스트와 형태를 함께 표시한다. 키보드 조작, 명시적 라벨, 반응형 레이아웃을 유지한다.
- 공통 토큰은 `src/ui/styles.css`의 색상·경계·간격 체계로 관리하고, 재사용 컴포넌트는 기능이 구체화되면 분리한다.

## 물리 모듈 설계

`src/physics`는 React에 의존하지 않는 순수 TypeScript 계층이다. 내부 계산은 SI(m, kg, s, rad)로 통일하고 단위 변환 및 반올림은 UI 경계에서만 수행한다. `EllipticOrbit`는 긴반지름, 이심률, 표준중력계수를 명시적으로 받는다. 궤도 주기는 `T = 2π√(a³/μ)`, 속력은 비바 방정식 `v = √(μ(2/r − 1/a))`, 위치는 원뿔곡선 방정식을 사용한다. 시간에서 위치를 구하는 함수는 평균근점이각에서 케플러 방정식을 뉴턴 반복으로 푼다.

유효하지 않은 값은 조용히 보정하지 않고 `RangeError`로 거부한다. 다음 단계에서는 함수별 단위 테스트를 추가해 원궤도(`e=0`), 근일점/원일점, 주기, 케플러 방정식 잔차, 경계값과 수렴 실패를 검증한다. 현실의 행성은 섭동·경사·상호작용이 있으므로 두 천체 문제 결과는 이상 모델로 표시하며 NASA/JPL 자료의 epoch/좌표계/단위를 데이터 출처와 함께 기록한다.

## 차시 개발 범위

1. 타원 궤도: 이심률 조절, 초점/태양 표시, 학생 예측·관찰 기록. 첫 기능 구현 대상.
2. 면적 속도와 조화 법칙: 동일 시간 면적 비교, 행성 자료 표와 `T²/a³` 비교.
3. 화성 전이: 원형·동일평면의 이상 호만 전이, 타원 전이와 반주기 이동 시간. Δv는 확장 항목.
4. 실제 임무 비교: 발사·도착 날짜와 비행 시간 출처, 이상 모델과 차이, 모델 가정 성찰.

각 차시는 도입 질문, 조작/관찰, 기록, 개념 정리, 교사용 요약으로 구성한다. 외부 자료를 넣을 때는 출처, 기준시점, 단위, 값의 정밀도를 함께 보존한다.

## 실행과 배포

- 개발: `npm install` 후 `npm run dev`
- 프로덕션 산출물 확인: `npm run build`, 필요 시 `npm run preview`
- GitHub Pages: 저장소 Settings → Pages에서 GitHub Actions를 소스로 선택하고 `main`에 푸시한다. `.github/workflows/deploy.yml`은 저장소 이름을 base path로 빌드한다.
- 사용자/조직 페이지처럼 루트 경로에 배포할 경우 workflow의 `VITE_BASE_PATH` 값을 `/`로 조정한다.

## 다음 개발 순서

1. 케플러 제1법칙 시뮬레이션을 물리 함수와 연결하고, 이심률·초점·근일점/원일점 값의 의미를 설명한다.
2. 입력 범위, 단위 표시, 시각화 축척, 접근성, 좁은 화면 동작을 확정한다.
3. 물리 모듈 단위 테스트를 설정하고 분석해와 독립적으로 검증한다.
4. 교사/학생 피드백을 반영한 뒤 제2·3법칙, 전이 궤도, 실제 임무 자료 순으로 개발한다.
5. 각 차시 완료 시 콘텐츠 정확성, 출처, 브라우저 동작을 검토한 후 Pages에 배포한다.
