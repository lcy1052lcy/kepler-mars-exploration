# 프로젝트 구조 및 개발 청사진

## 목표와 구현 경계

고등학생이 먼저 예상하고, 시뮬레이션을 조작해 관찰한 뒤 결과를 설명하도록 돕는 4차시 웹 애플리케이션입니다. 공통 차시 메뉴와 화면 체계를 사용하며, 차시별 기능은 `src/features`에 분리합니다. 현재 1차시 케플러 제1법칙과 2차시 케플러 제2·3법칙을 구현했습니다. 3·4차시는 아직 구현하지 않습니다.

`PLAN.md`가 교육 목표, 활동 순서, 시간 배분의 기준입니다. 콘텐츠나 차시 순서를 바꾸어야 한다면 구현 전에 근거와 수정안을 검토합니다.

## 디렉터리

```text
src/
  content/       차시 메타데이터, 행성 자료와 출처
  physics/       UI와 독립된 SI 단위 궤도 계산 함수
  features/
    lesson-02/   제2·3법칙 단계형 탐구와 시각화
  ui/            공통 앱 셸, 차시 이동, 디자인 스타일
  main.tsx
tests/           물리 모듈 자동 테스트
docs/            교육 기획 및 개발 기록
.github/workflows/ GitHub Pages 배포
```

1차시 화면은 기존 공통 앱 셸 안에 두고, 추가 차시는 기능 폴더에서 독립적으로 구현합니다. 반복되는 UI가 실제로 늘어날 때 공통 컴포넌트로 옮겨 기능별 구현이 불필요하게 결합되지 않도록 합니다.

## UI 및 학습 원칙

- 밝은 바탕과 간결한 상단 차시 메뉴를 사용하고 천체 관찰 영역만 어둡게 표현합니다.
- 단계마다 학습 목표, 조작 안내, 학생 응답, 응답 뒤 피드백, 다음 단계 이동 순서를 둡니다.
- 정답 설명은 관찰·응답 전에는 노출하지 않습니다. 예측과 단계별 관찰 기록은 서로 분리합니다.
- 그래프와 천체 그림은 화면 폭이 달라져도 원래 축척을 유지합니다. 색뿐 아니라 형태·문구·기호도 함께 사용합니다.
- 실제 행성 자료와 학습용 이상 모델을 분명히 구분하고, 출처·단위·반올림 수준을 표시합니다.

## 물리 모듈 설계

`src/physics`는 React에 의존하지 않는 순수 TypeScript 계층입니다. 계산은 SI(m, kg, s, rad)로 통일하고 단위 변환과 반올림은 UI에서 수행합니다. `EllipticOrbit`은 긴반지름, 이심률, 표준중력계수를 명시합니다.

- `ellipseGeometry`: 타원의 단·장축, 초점 간격, 근일점 및 원일점 거리
- `eccentricAnomalyFromMean`, `stateAtTime`: 케플러 방정식으로 시간에 따른 행성 위치 계산
- `stateAtTrueAnomaly`: 궤도 위치와 비바 방정식 기반 속력 계산
- `orbitalPeriodSeconds`, `thirdLawRatio`: 공전주기와 제3법칙 비율
- `sweptAreaBetweenTimes`: 면적 속도 일정 관계에서 동일 시간 쓸린 면적을 해석적으로 계산
- `distanceTraveledBetweenTimes`: 케플러 상태 속력을 심프슨 적분해 이동 거리 계산

물리 계산은 `tests/physics.test.mjs`에서 UI와 별도로 검증합니다. 이상적인 두 천체 모델은 실제 행성의 섭동과 궤도요소 변화를 모두 표현하지 않으므로 교육용 모델의 가정을 화면에서 안내합니다.

## 차시 구현 범위

1. **케플러 제1법칙:** 이심률 조절과 실제 행성 비교, 초점 및 긴반지름 표시, 단계별 관찰·정리.
2. **케플러 제2·3법칙:** 같은 시간 면적 비교, 근일점/원일점 속력 및 이동 거리 비교, 실제 행성의 `P`-`a` 및 `P²`-`a³` 그래프, 세 법칙 정리. 교육용 예시 궤도의 이심률 0.62와 NASA Goddard Fact Sheet 자료를 사용합니다.
3. **화성 전이:** 이후 개발 범위. 이상적인 동일 평면 호만 전이와 시간·속도를 다룹니다.
4. **실제 임무 비교:** 이후 개발 범위. 실제 탐사 임무 자료와 이상 모델의 차이를 비교합니다.

2차시 행성 자료는 NASA Goddard Planetary Fact Sheet의 평균 태양 거리(긴반지름의 근삿값)와 공전주기를 사용합니다. 단위 변환과 반올림은 자료 선택 UI에서 수행하며, 축은 전체 행성 범위를 읽을 수 있도록 로그 눈금으로 표시합니다.

## 실행과 배포

- 개발: `npm install` 후 `npm run dev`
- 검증: `npm test`, `npm run build`
- 프로덕션 산출물 확인: `npm run preview`
- GitHub Pages: 저장소 Settings → Pages에서 GitHub Actions를 배포 소스로 선택합니다. `.github/workflows/deploy.yml`은 저장소 이름에 맞춘 base path로 빌드합니다.
- 사용자/조직 페이지처럼 루트 경로에 배포하면 workflow의 `VITE_BASE_PATH`를 `/`로 조정합니다.
